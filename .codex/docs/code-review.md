# 代码审查清单

触发：CR、找 Bug、质量或精简。适用 `rate-sync/`、`monitoring/` 和部署脚本。

## 原则

- 从入口追到状态变化、外部副作用和清理；Findings-first，只报告有触发条件、证据和影响的问题。
- 仅审查时停在建议；要求修改时做最小修复，并复查调用点、测试和完整 diff。
- 不报告纯风格偏好；无法确认时说明需要的外部或运行时验证。

## 精简与边界

- 只处理有证据的重复、死代码、职责混杂、隐藏副作用和不必要耦合，不以减少行数为目标。
- 保持高内聚、低耦合和单一主要职责；复杂度影响测试、修改或定位时才拆分函数/文件。
- 不为单次使用增加工厂、全局状态或抽象；API 最小，`Get` 不隐藏写入，`Try` 确实可能失败。
- 删除参数、重命名或收窄 API 前检查全部调用点；不用静态/全局状态掩盖参数问题。
- 一次精简只做一个主题；命名、错误和格式沿用模块风格，注释只解释原因和限制。

## 正确性

- 两个 Go 模块保持独立；配置、业务、持久化和 HTTP/部署边界可追踪。
- 覆盖错误/超时、空值、边界值、重复调用和幂等；SQL 参数化，事务失败不留半完成状态。
- 账号/分组 ID、水位、倍率、历史证据、告警和待发布目标不可混用；旧缓存不冒充本轮成功。
- `context.Context` 贯穿 IO/SQL/HTTP/循环；关闭 Rows、Body、连接、ticker、channel 和 lease。
- 检查 goroutine 泄漏、阻塞、shutdown 竞态；重试有边界且不重复写入或消费水位。

## 部署与安全

- PowerShell 检查严格模式、异常和外部命令退出码；删除/UAC/卷/运行目录目标必须受限。
- 部署不覆盖 ProgramData 配置、状态卷或密钥；容器替换先确认健康。
- 密钥、密码、代理认证和 Token 不进入日志、错误、状态文件或测试快照。
- 保持监控 SSRF/代理/只读边界和 rate-sync Admin API 写入边界。

## 性能、测试与输出

- 只优化有样本的热点；检查重复查询、无界集合、过高并发、未关闭响应和多余序列化。
- 修复缺陷增加最窄回归用例；两个模块分别运行 `go test ./...`，脚本运行 PowerShell AST 解析。
- 按 P0/P1/P2/P3 输出问题、触发条件、影响、文件/行号、证据和处理结果；报告验证及残余风险。
