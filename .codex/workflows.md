# Sub2ApiExt 工作流

由根 `AGENTS.md` 按任务路由；产品和部署行为以服务 README 为准。

## Triage Issue

- 追踪触发、调用链、外部副作用和退出路径；优先修根因。
- 在最窄模块增加回归测试，再做最小修复；运行对应 `go test ./...`。
- 部署脚本改动做 PowerShell 解析检查；真实上游不可用时用 fake 和明确的手工复现，不假装已验证。

## Logic Bug Review

- 按入口、状态/数据流、失败/重试、事务/租约、并发取消和清理组成完整链路。
- Findings-first，只报告有触发条件、证据和可观察影响的问题；修复后复查调用点和完整 diff。

## CR 精简

- 先确定行为基线和允许范围，只处理有证据的重复、死代码、职责混杂、隐藏副作用或耦合。
- 一次精简只做一个主题，不混入重命名、格式化、依赖升级或功能变更。
- 详细检查见 `docs/code-review.md`；改后复查调用点、边界、完整 diff 和最窄测试。

## 部署兼容

- 修改部署或配置前比较 ProgramData 配置、卷和容器名称，确认不丢数据、不启动重复 Worker。
- 检查外部命令退出码、健康检查、端口/防火墙、UAC 路径和凭据脱敏；不改上游源码或数据库结构，除非用户明确要求。

## Grill Me

- 先读代码、README 和配置；一次只问一个会改变实现方向的关键问题，并说明更简单方案和不可逆风险。

## 验证

- `rate-sync`、`monitoring` 分别运行 `go test ./...`；脚本改动运行 PowerShell AST 解析。
- 需要网络、Docker、PostgreSQL 或 GPU 时记录前置条件和未覆盖风险。

## 文档

- 稳定规则放 `AGENTS.md`，领域说明放 `.codex/docs/`，短流程放本文件，历史迁移放 `.codex/archive/`。

## Git 提交流程

仅用户明确要求提交或整理提交时执行：

- 先看 `git status --short`、`git diff --stat` 和目标文件完整 diff；排除无关改动，不使用 `git add -A`、`git commit -a` 或宽泛路径。
- 一条提交只表达一个主题；标题必须是中文 `【模块】动词开头的简单说明`，不使用 `feat:`/`fix:`，建议不超过 30 字。
- 正文写改动与验证，命令显式列出文件；提交后核对 hash、文件数、增删行数和验证结果，不改写公共历史。
